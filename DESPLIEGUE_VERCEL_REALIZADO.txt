PASO 8. PROBLEMAS ENCONTRADOS Y CORRECCIONES
--------------------------------------------
1) Conflicto con el preset Services
   Ver: "The top-level properties installCommand, buildCommand,
   outputDirectory, framework cannot be used with services".
   Causa: Vercel CLI 65 creó el proyecto con el preset Services y no admite
   propiedades de build en la raíz de vercel.json.
   Solución: dejar el build en la sección services
   (root ".", framework "angular", buildCommand "npm ci && npm run build").

2) Todos los archivos JS se servían como HTML
   Causa: la reescritura /(.*) -> /index.html se aplicaba antes que el servicio
   y capturaba también JS, CSS y fuentes (todo devolvía index.html de 9.7 kB).
   Solución: primero se limitó a rutas sin extensión y finalmente se eliminó:
   vercel.json solo enruta el tráfico al servicio Angular, que resuelve el
   fallback SPA para rutas desconocidas. Verificado con main-*.js, chunk-*.js,
   styles-*.css, fuentes, imágenes, site.webmanifest y robots.txt.

3) SITE_URL no llegaba al build
   Causa: la variable se creó como tipo "Secret"; el bundle siguió mostrando
   el dominio por defecto.
   Solución: se eliminó y se volvió a crear como Config (--no-sensitive),
   porque el dominio es información pública. Tras el nuevo deploy, el canonical
   quedó en https://polleria-don-pepito.vercel.app/<ruta>.

4) Página en blanco en producción
   Error en consola: "supabaseUrl is required".
   Causa: SupabaseService creaba el cliente aunque no hubiera credenciales.
   Solución: src/app/core/services/supabase.service.ts crea un cliente inerte
   cuando faltan datos y registra un aviso; la app queda en modo demo sin
   claves en el bundle.
   Complemento: src/app/app.component.ts sincroniza canonical y og:url con
   SITE_URL en tiempo de ejecución.
